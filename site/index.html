The problem

One MCP server. Seven editors. Seven config files.

Claude Code, Cursor, VS Code, Windsurf, Antigravity, Gemini CLI and Claude Desktop each keep MCP servers in their own file and format. A new Supabase account used to mean deleting the entry, pasting a new token, and doing it again in every editor.

Named instances

A server template plus settings and credentials. Run as many as you need: supabase@dev, supabase@prod, github@work.

Per-project remapping

Bind an entry name to an instance per folder. Switch it from dev to prod and mcpm rewrites every selected editor's config.

Secrets in the keychain

Tokens live only in Windows Credential Manager, macOS Keychain or Linux Secret Service — never in a config file.

Safe writes

mcpm only touches entries it owns, refuses to overwrite yours, and backs up every file before writing.

How it works

Config files only say mcpm run.

Every entry mcpm writes is a tiny launcher. Secrets load at launch, from the keychain, so the file stays safe to commit.

~/code/shop-app/.mcp.jsonClaude Code
{
  "mcpServers": {
    "supabase-dev": {
      "type": "stdio",
      "command": "mcpm",
      "args": ["run", "supabase@dev"]
    },
    "supabase-prod": {
      "type": "stdio",
      "command": "mcpm",
      "args": ["run", "supabase@prod"]
    }
  }
}  // no tokens here
At launchmcpm run supabase@prod
  1. 1
    Editor starts the entryClaude Code, Cursor or any client runs mcpm run <instance>.
  2. 2
    Secrets come from the OS keychainThe shim reads the instance's credentials, which never go into a config file.
  3. 3
    The real server is spawnedThe template renders the command and environment, then starts the server.

Get started

Build it from source.

Needs Rust (stable), Node 20+, pnpm, and the Tauri prerequisites for your OS.

Terminal
# clone
git clone https://github.com/Srikrishnan2004/mcpm.git
cd mcpm

# install the launcher shim so editors can run `mcpm`
cargo install --path crates/cli

# run the desktop app
cd apps/desktop
pnpm install
pnpm tauri dev

New server templates and client adapters are the most valuable contributions — see CONTRIBUTING.md.
